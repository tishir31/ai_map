How the Physical AI Tracker actually works

You asked a fair question: how live is this, and where does the data come from? Here is an honest, no-jargon map of the pipeline today, what is genuinely live, what is scaffolded but not wired, and what is on the roadmap.

Current state, in one sentence. The tracker is a static website. All ~140 companies are baked into the JavaScript file your browser downloads. The numbers you see come from a curated seed list, plus any edits you make in your own browser. Nothing on this site polls Gmail, Pitchbook, or the open web in real time today.

Refresh button

What pressing "Refresh data" actually does

The button is intentionally simple today, because there is no live backend to call yet. Here is the exact sequence:

You click Refresh data

The button enters a spinning "Refreshing…" state.

If a backend endpoint is configured future

The page posts to VITE_REFRESH_ENDPOINT. That endpoint is meant to kick off a server-side run of the ingest + verify pipeline. None is wired today.

The page hard-reloads with a cache-buster live

It appends ?r=<timestamp> to the URL and reloads. This guarantees you fetch the freshest deployed JavaScript bundle — useful right after we ship an update.

New bundle = new seed data live

When we add companies or fix figures, we redeploy the site. The next refresh pulls those changes in. Your own manual edits and tags survive — they live in localStorage, not in the bundle.

Translation: refresh is a "pull the latest version of this website" button, not yet a "go fetch tonight's news" button. The second behaviour is what the Gmail integration below is building toward.

Gmail integration

How the Gmail flow is designed to work

The plan is to have the system sweep your inbox for newsletters (The Information, Axios, etc.) and surface every Physical AI funding / M&A / partnership signal it finds — but never write to the public dataset without you approving first. Eight steps:

Authenticate Gmail scaffold

OAuth handshake against your Google account. The credentials live on your machine, not on this site.

Sweep inbox for matching newsletters scaffold

A query like from:hello@theinformation.com newer_than:7d pulls candidate threads.

Extract company / amount / counterparty scaffold

Regex today, LLM later. The extractor builds a candidate row, not a confirmed row.

Dedupe against existing rows live

If "Anduril $4B" already exists, the candidate is flagged as a likely duplicate, not a new entry.

Land in the Review Queue live

You see the candidate in the Review Queue tab. Gmail snippets stay private — only sanitized text is shown.

You approve, merge, or reject manual

This is the only step that can write to the database. No bypass.

Verifier flags stale or unsourced records live

The "Verify numbers" drawer lists anything older than 90 days, missing a source, or marked low-confidence.

Daily cron runs the whole pipeline scaffold

A GitHub Action is committed (.github/workflows/refresh-data.yml). It runs at 14:00 UTC daily and opens a pull request rather than writing directly — preserving the review gate.

Editing companies yourself

The manual update path you just got

On any company card on the Company Profiles page you now have two new buttons:

Edit a company

Update the overview text, subsector, geography, website. Your change overrides the seed for that field. The seed is never touched.

+ Activity on a company

Add a fresh funding round, M&A, partnership, customer contract, etc. You set the date, deal value, investors, source URL, and confidence.

Both kinds of edit are saved to your browser's localStorage, so they survive refreshes and are scoped to this device. The sidebar shows a live count of edits and a "Reset to seed" button if you want to start over. When we ship a new build that contains the same fact, your override is preserved — it sits on top of the seed.

FAQ in plain English

Quick answers

If I edit a company on my laptop, does my colleague see it?

No. Edits are stored in your browser. To share, either Export to Excel or ship the edit into the seed (we can commit it into the dataset together).

How "live" are the numbers?

As live as the last deploy. The Verifier flags anything older than 90 days; that is your audit list to re-check against the source URLs you can click.

What happens if a press release moves URL?

The link will 404. The Verifier flags broken/placeholder hosts. Future enhancement: nightly cron that HEAD-pings each URL and downgrades confidence on 4xx/5xx.

Why isn't the Gmail pipeline already running?

It requires either (a) a server with your OAuth credentials, or (b) a local desktop run. The current site is a static deploy on Vercel — no server-side code runs here yet.
