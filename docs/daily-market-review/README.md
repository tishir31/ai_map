# Bounded daily public market review

Activated in production on 2026-09-18 after source PR13 and deploy PR19 merged; production commit `37c39fe`. Schema migration `20260918225507` and scheduler migration `20260918231042` are applied. The first bounded dispatch completed with no selected candidates; positive publication is demonstrated by isolated fixtures, not by this live run.

The fixed `/api/market-review-daily` route is multiplexed through the existing pipeline function, preserving the Vercel function count. It requires job/date-scoped HMAC even outside production; generic Cron/manual secrets, wrong jobs and stale run dates are rejected. Vault resolution uses the existing owner/service boundary; no new credentials/provider/subscription.

## Evidence and publication contract

Each UTC run freezes ≤10 newest pending recent-public candidate IDs, public-only field fingerprints, selection order and known-company snapshots in service-only RLS tables. Seven inclusive UTC event dates; no Gmail IDs or mailbox/snippet/extracted-text fields read/copied. One outstanding run resumes exact saved IDs across date rollover before another run is selected. Each candidate has at most two leased attempts, a90s lease and5minute provider-error retry delay. At most one active leased task/run and one task/request, one saved-source page read (existing SSRF/DNS/redirect gate,9s total deadline) and at most one configured Gemini call (25s timeout). No search/model-selected URL or operation. A service-only actual-UTC-day claim ledger additionally limits processing to10 distinct frozen tasks and20 total attempts/day, including carried-over work; budget exhaustion retains pending tasks for a later UTC day. Maximum20 source-page reads/model calls/day, often fewer for immediate holds. After15:10UTC, completing a carry-over initializes today’s missing batch without a second provider call; before the collection window it leaves the ordinary daily launch to select it. Event recency is rechecked against the actual review/publication day.

Publication v1 deliberately requires exactly one previously known company (rechecked at publication) with a fixed trusted registry website, HTTPS canonical issuer page on that exact domain/subdomain, explicit company/date/financing-status/physical-relevance capture quotes, explicit USD or US$ amount, and no conflict with staged date/value. The date passage must be exactly a source-boundary date prefix plus one issuer-led financing sentence. The sentence accepts only a direct issuer/affirmative verb/one US-dollar amount/in-round-financing-or-funding/optional exact lead form; amount, issuer, round and lead quotes must all be contained in that sentence. Physical application must be issuer-led and name an actual robotic/sensing/simulation application. Denied/corrected/canceled/withdrawn/pending/archive/historical/debt/valuation source contexts and nonempty staged cautions are held. Model qualifying:false is uncertainty held, never proof of nonqualifying. Valuation/debt/credit/revenue tokens are not equity financing evidence. Round is optional if unasserted; a staged asserted round must match a supported exact quote. Lead is optional and appears publicly only with an exact non-negated lead quote attached to the event. Descriptions are deterministic, attributed paraphrases; confidence remains `reported`, honest agent audit attribution and actual publication timestamp are enforced.

Unknown/new companies, nonofficial or unresolved Google RSS canonicals, unsupported event types (including M&A/commercial status), non-USD ambiguity, conflicting values/dates/identity and incomplete quote evidence are held. This lane reviews their selected disposition but cannot automatically resolve every case or guarantee new events daily. Existing analyst review remains necessary for those cases. Gate breadth is disclosed in health.

SQL atomic finish/publisher checks the live candidate/company fingerprints, valid lease, excluded IDs/company, same-company event/source lookup with matching event date/value and active exclusion/public-safe duplicate gates, exact capture hash/quotes/USD token/date, deterministic source/activity IDs and public status/confidence. Locks against other market writers protect the narrow transaction, with3s lock timeout. Source precedes activity; candidate approval occurs last, with canonical URL and durable evidence note. Private per-attempt results retain provider failures and provenance across retry, while error counters count terminal errors. Unexpected existing deterministic rows abort. Same event/source with conflicting date/amount or private/placeholder/Google/unapproved/excluded source is held; a verified existing public event is a duplicate, retaining its original audit. Held/duplicate/nonqualifying/error candidates otherwise remain untouched. Publication and all private disposition/counter writes are one transaction, so telemetry failure cannot mark completion while losing its publication audit. Repeated finish after commit is a no-op.

Runs aggregate selected/reviewed/published/held/duplicate/nonqualifying/error/not-reviewed. Reviewed excludes provider errors; `selected=reviewed+notReviewed`, errors are included within notReviewed. Terminal errors produce runpartial. `completed` with selected0 means no pending candidates selected in the defined recent-public subset, not fieldwide absence of events. Public-web collector-window completed/partial/unknown is captured separately without requiring a Gmail run; a completed empty review does not turn a partial collection into success.

## Recorded apply order and rollback

Both SQL files are migration templates for review or a fresh compatible environment. The migrations above are already applied in production; do not rerun their CREATE statements there.

1. Apply `review-schema.sql` before enabling route dispatch. Production applied it as migration `20260918225507` through Supabase apply_migration. Review RLS and invoker/service-only grants/security advisors. Private captures/frozen fingerprints are never browser-readable.
2. Deploy reviewed backend. Check anonymous daily route401, health200 and `publicMarketReview` configured/unknown semantics. No provider calls/DB writes occur for failed authorization. Validate exact backend hashes through the release manifest.
3. Apply `review-scheduler.sql` **only after the authenticated fixed route exists**. Production applied it as migration `20260918231042`. It adds the fixed dispatch job at15:10/15:40/16:10/16:40 UTC, after the collector window. Existing postgres-owned two-minute ecosystem resumer now calls the independent review continuation before its existing cadence-aware graph continuation, with review-only exceptions isolated so they cannot block graph dispatch. Weekly/daily/monthly/quarterly and collector schedules/credentials remain. Both new private resumer and existing private dispatcher stay owner-only, securityinvoker.
4. One authorized dispatcher call on a fresh UTC day initiates the bounded review. Do not reset historical successes or manufacture eligible candidates to demonstrate publication. Inspect source/model error, held/noqualifying/duplicate counters and final active public projection, with no raw captures/IDs in health. Scheduler202 means accepted continuation; final partial/errors remain visible rather than falsely complete.
5. Rollback: deactivate the new daily review job and restore the captured previous shared resumer definition to stop review continuation. Preserve service-only runs/tasks and approved audit history; never erase cursors or undo existing canonical activity content by blanket deletion. Code rollback can retain additive tables; avoid dispatching the new job before compatible code is restored.
