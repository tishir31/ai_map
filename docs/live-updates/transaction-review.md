# Transaction coverage repair

The September 16–October 13 audit found 75 pending financing candidates and six pending M&A candidates. These were leads, not 81 verified missing deals: 29 came from public discovery and 52 from private discovery. The existing published ledger had only ICON, Multiply Labs and Vinci after September 15.

Discovery accepted financing only and frequently retained Google News redirect URLs. Review repeatedly held unfamiliar issuers, rejected legitimate debt/native-currency formats, and lacked an acquisition publication path. A recent latest-event date therefore did not establish continuous market coverage.

`market-transaction-review.sql` extends the existing private review functions. Apply the tested SQL before deploying the corresponding worker. It preserves the daily ten-candidate/twenty-attempt limits. Unchanged holds are skipped for seven days; changed candidate, issuer or registered-source inputs become eligible immediately. New issuers require a trusted issuer wire, an issuer-supplied HTTPS website and a readable matching homepage. Ambiguous currencies and unverified identities remain held. Automatic profiles stay in Other companies until editorial classification.

Apply `transaction-resume.sql` afterward so the existing two-minute continuation also detects newly arrived acquisitions and unfamiliar issuers. It uses the same eligibility, unchanged-hold and daily-cap rules; the existing scheduler authentication and private execution permissions remain in place.

Publication binds the current financing or acquisition to the issuer, date, amount, currency, event status, physical application and exact source capture/hash. Equity, debt and announced/closed acquisitions stay distinct. Native amounts have no invented USD conversion. The authenticated database wrapper validates this independently of the worker. The public coverage function exposes aggregate unresolved counts only; its `marketCompleteness` is always `not-established`.

The user-authorized catch-up has a separate private audit in `market_recovery_events` and uses `publish_market_recovery`, with the same source/exclusion checks and idempotent activity identities. Source captures and private discovery records must not be committed to this public repository. The prepared September/October batch includes SiMa.ai, World Labs/AMD, Waymo, Mecka AI, Minerva Humanoids, Fortem Technologies, D-Robotics, Parallel Systems, Fortastra, Noetive, TacnIQ.ai and Nearhuman. Preparation is not evidence of successful production publication; verify the recovery audit and public snapshot after execution.

Validation: transaction and source-resolution fixtures, isolated PostgreSQL publication/conflict/ownership/privacy tests, existing reviewer/collector/auth/health contracts, and a repeated isolated execution of the complete catch-up SQL. Verify production deployment and actual published event dates after applying the database changes. The next collection run uses the new acquisition and engineering/world-model queries; previously frozen runs retain their original query plan.
