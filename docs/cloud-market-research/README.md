# Cloud market research

The user requested migration of the four-hour desktop research/review/publishing automation to always-on infrastructure. This worker runs in the existing Vercel deployment, uses its existing Gemini credential, and stores progress, captures, evidence, decisions and retries in Supabase. It never needs a desktop process or a local checkout at runtime. The cloud model defaults to `gemini-3.5-flash-lite`, with an optional `CLOUD_MARKET_GEMINI_MODEL` override. The initial legacy-model invocation returned HTTP429; the current model follows [Google's new-project recommendation](https://ai.google.dev/gemini-api/docs/models). Provider errors retain only allowlisted quota identifiers and retry metadata, never raw error bodies or credentials.

Supabase cron wakes the signed worker every minute when work is due. The database starts one research cycle per four-hour UTC slot, covering six market themes with at most eight discovered events each, plus up to twenty existing public exceptions. A 48-hour overlap and a persisted completed-window cursor handle missed intervals. Collection and review execute in separate leased tasks; expired leases recover, transient errors back off, and attempts are bounded. The independent existing hourly collector remains active.

Discovery uses grounded Google Search, including non-English sources and companies outside the current database. Search output only stages reports. Publication fetches the original public source with DNS/redirect protection; it requires an established company/official-source binding or the existing wire-to-issuer/homepage proof. A separate model pass checks each nonfinancial summary against the complete capture. Both JavaScript and SQL independently bind exact evidence passages, issuer, event date, source authority, type, status and capture hash. Nonfinancial updates have no deal value. Financial transactions continue through the existing independent `assert_market_transaction` gate, and their descriptions are reconstructed from verified evidence in SQL.

Uncertain or unavailable evidence remains held with a durable reason and periodic source-search follow-up. Active exclusions and denied origins remain enforced. Private mail never enters this lane. There is no mock fallback. Adding search coverage does not establish exhaustive market completeness.

`/api/cloud-market-research` requires the existing signed scheduler authentication with the separate `market-research` job scope. `/api/cloud-market-research-status` exposes only operational counts, timestamps, coverage gaps and coarse failure reasons. Captures, leases, private candidate data and credentials remain inaccessible to anonymous/authenticated clients. Pipeline health also includes this cloud status.

Deployment sequence: apply the schema migration; deploy and verify production; invoke `private.dispatch_cloud_market_research()` as the database owner; verify the actual cloud execution; enable the one-minute cron via `cron.schedule('physical-ai-cloud-market-research','* * * * *','select private.dispatch_cloud_market_research()')`; then pause the desktop heartbeat. Never print the scheduler root or signed headers. Scheduling and dispatch remain in the database, independent of Codex.

Validation: `node --test tests/*.test.cjs`; existing scheduler, router, transaction and review tests; `ECOSYSTEM_PGLITE_PATH=... node scripts/test-cloud-market-sql.cjs`; full public-site CI and release manifest checks. SQL tests exercise actual schema/functions in isolated PostgreSQL, not mocked publication logic.
